请从零开发一个能断点恢复的异步采集调度器，将本地模拟网站“分类→分页→详情”的数据采入 SQLite。使用 Windows 原生 Python 3.12，可用 asyncio 和 HTTP 库；不使用现成爬虫调度引擎、Docker 或外部网站，模拟站点也由你实现。

1. 网站数据在一次采集中固定，但链接会重复、成环，页面会继续发现新任务。为任务设计稳定身份并持久化去重；父任务完成前，发现的后续任务必须已可靠保存，不能重启后漏掉分支。
2. 支持多个 worker 进程，限制并发和内存队列。worker 超时或崩溃后任务可重新领取，旧 worker 的迟到结果不得提交。503和超时需有限退避重试，耗尽后明确失败，不能假装完成。
3. 任务结果、后续任务和完成状态必须原子提交。在“收到响应后”“保存结果但尚未提交”“提交成功但尚未确认”三个时点强制结束进程，使用原数据库重启后，任务集合与采集结果须和无故障运行一致，不漏记录、不重复落库。
4. 不能因为队列暂时为空就结束；仍有执行中或等待重试的任务时，应继续等待。只有所有已发现任务成功完成才能宣布采集完成；失败或缺记录要列明。提供可查询的任务状态、重试次数和完成依据。

自建有重复链接和多级分页的样例，用可控同步点验证并发抢任务、旧 worker 迟到、503重试及三个崩溃时点，逐项对照预期任务和结果；答案仅供测试读取。交付命令行入口、模拟站点、自动化测试和 Windows 运行说明，记录实际结果及未完成项。无需图形界面或外部附件。
